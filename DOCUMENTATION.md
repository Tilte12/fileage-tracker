# Документация FileAge Tracker

## 1. Описание проекта

FileAge Tracker — плагин для Visual Studio Code, написанный на языке TypeScript.

Плагин предназначен для просмотра истории изменений проекта с помощью Git.

Он позволяет получать информацию о последних 20 коммитах, их авторах, датах, описаниях и изменённых файлах.

Также плагин подсчитывает количество коммитов каждого автора.

## 2. Структура проекта

Основные файлы проекта:

- `src/extension.ts` — основной код плагина.
- `package.json` — настройки плагина и регистрация команды.
- `tsconfig.json` — настройки компилятора TypeScript.
- `README.md` — описание проекта и инструкция по использованию.
- `DOCUMENTATION.md` — техническая документация.

## 3. Архитектура плагина

Плагин использует Visual Studio Code Extension API для взаимодействия с редактором и Node.js для запуска команд Git.

Работа плагина состоит из следующих этапов:

1. Пользователь запускает команду FileAge: Show Project History.
2. Плагин получает путь к открытой папке проекта.
3. Формируется массив аргументов для команды `git log`.
4. Git возвращает историю последних 20 коммитов.
5. Плагин выводит полученную историю в панель Output.
6. Программа анализирует полученный текст и подсчитывает количество коммитов каждого автора.
7. Статистика авторов также выводится в Output.

## 4. Основные функции и методы

### activate()

Главная функция расширения.

Вызывается при активации плагина и регистрирует команду `fileage-tracker.scanFiles`.

### vscode.workspace.workspaceFolders

Используется для получения списка папок, открытых в VS Code.

В текущей версии плагин работает с первой открытой папкой.

Если папка не открыта, выводится сообщение об ошибке.

### execFile()

Функция модуля Node.js `child_process`.

Используется для запуска внешней программы Git с необходимыми аргументами.

После выполнения команды возвращает результат в переменной `stdout`.

Если команда завершилась с ошибкой, плагин выводит сообщение пользователю.

### git log

Команда Git для получения истории изменений.

Используемые параметры:

- `-20` — получение последних 20 коммитов.
- `--date=short` — короткий формат даты.
- `%h` — сокращённый идентификатор коммита.
- `%an` — имя автора.
- `%ad` — дата коммита.
- `%s` — описание коммита.
- `--name-only` — список изменённых файлов.

### Map

Структура данных, которая используется для хранения количества коммитов каждого автора.

Ключом является имя автора, а значением — количество его коммитов.

Например:

```text
Егор → 8
Максим → 5
Андрей → 3
```

## 5. Алгоритм подсчёта коммитов

Для подсчёта коммитов используется следующий алгоритм:

1. Создаётся пустая структура `Map`.
2. Полученная история Git разбивается на строки с помощью `split()`.
3. Цикл `for` последовательно перебирает строки.
4. Если строка начинается с `Автор: `, из неё извлекается имя автора.
5. Проверяется, сколько коммитов этого автора уже было найдено.
6. Счётчик увеличивается на единицу.
7. После завершения цикла выводится статистика всех найденных авторов.

Таким образом, плагин самостоятельно обрабатывает информацию, полученную от Git.

## 6. Обработка ошибок

В плагине предусмотрены две основные проверки:

- Если в VS Code не открыта папка проекта, выводится сообщение `Откройте проект!`.
- Если команда Git завершилась с ошибкой, выводится сообщение `Не удалось получить историю Git`.

## 7. Ограничения

- Для работы необходим установленный Git.
- Проект должен содержать Git-репозиторий с историей коммитов.
- Обрабатываются только последние 20 коммитов.
- Статистика строится по именам авторов, поэтому одинаковые имена объединяются.
- Незакоммиченные изменения не учитываются.
- Плагин показывает названия изменённых файлов, но не изменения отдельных строк кода.

## 8. Заключение

В ходе разработки плагина были использованы возможности VS Code Extension API, выполнение внешних команд Node.js, массивы, циклы и структура данных `Map`.

Реализован просмотр Git-истории проекта и простой алгоритм подсчёта активности авторов коммитов.
